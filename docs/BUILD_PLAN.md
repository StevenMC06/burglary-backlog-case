## Non-negotiables (from the case and the judges)
- Synthetic data plus public Seattle geography only. No real people. No facial recognition. No names: offenders and sellers are opaque refs (`A-017`, `S-0421`).
- **AI suggests, humans decide.** Every assignment, series alert and victim message needs a human click, which is recorded in the hash-chained audit log.
- **Cases, not people:** linkage groups cases; it never names or scores a person or a neighbourhood.
- **Reproducible:** engine outputs are deterministic. Every packet claim carries a citation token `[CASE_ID:field]`. Engine version is stamped.
- **Simple for officers:** one screen, few clicks. The domain judge: "keep it really simple."
- Minimal dependencies. Don't add crates without a strong reason; never add a CLI-parsing crate or a rand crate.

## W2: datagen (`crates/casefile/src/datagen.rs`, `data/public/`, `data/seed/`)
1. **Public geography.** Fetch real burglary locations from Seattle Open Data "SPD Crime Data: 2008-Present" (Socrata `tazs-3rd5`, cos-data.seattle.gov or data.seattle.gov). Inspect the column names first; filter burglary offenses, take recent rows with coordinates. Keep only block address, lat/lon, beat, neighborhood (MCPP).
   - Save `data/public/seattle_burglary_points.csv` (≤ 6,000 rows) plus `data/public/SOURCE.md` (URL, query, date fetched, licence note).
   - Do the fetch once with a script or curl, not at datagen runtime; datagen reads the CSV.
   - Fallback if the network fails: a built-in table of ~40 Seattle neighbourhood centroids.
2. **`casefile datagen [--seed 7] [--cases 2000]`.** Deterministic in-house PRNG (splitmix64).
   - 2,000 cases over 365 days ending 2026-11-05 08:00 local; locations sampled from the public points (≤ 60 m jitter).
   - **40 planted series** (sizes 2–12, heavy tail; ~35% of cases). Each synthetic offender has: home point, radius 0.5–3 km, consistent MO (premise, entry point/method, time band, weekday habit, 2–3 preferred property types, 1–2 signatures), an active period of 3–10 weeks, and ≥ 1 day between offenses. Planted series must be spatiotemporally feasible.
   - Singletons draw MOs from realistic marginals.
   - **Clearance:** about 30% of series have one case `ClearedByArrest {arrestee_ref}`. Clear random singletons (distinct refs) until total clearance ≈ 13%.
   - **10 decoys:** groups of 3–5 real cases with very similar MO that violate a hard constraint: `spatiotemporal_infeasible` (overlapping windows, ≥ 12 km apart) or `conflicting_clearance` (two cases cleared to different arrestees). Record them in GroundTruth.decoys.
   - **Items:** 1–4 per case, consistent with the MO. Fictional brands (no real trademarks). ~60% of electronics have serials; some items have distinctive markings.
   - **Pawn ledger ~1,500 records:**
     - noise listings;
     - ~10% of traceable cases resurface 2–30 days after the offense, with serial formatting variants ("C02-XK1" vs "c02xk1");
     - traps: same model with a different serial, same model with no serial, a shared marking, and one item "pawned" before its burglary (impossible).
     - Record `pawn_truth`.
   - **SolvabilityFacts:** correlated sensibly. Window hours are realistic (residential daytime 6–10 h).
   - **Narratives:** officer shorthand with several templates per field (RP, UNK SUSP, POE, FE, "via rear slider", "screen cut", "ransacked MBR", times), 2–5 sentences. Serials appear in the narrative for some items. Every MO field must be recoverable from the text unless deliberately unknown.
   - **Demo queue (`data/seed/demo.json`):** 36 "overnight" cases reported in the last 12 h, `mo: None` (to be extracted). All other cases keep the generator MO. demo.json lists `queue`, plus hero picks:
     - `hero_series`: a 7-case series that includes one queue case and one case already cleared by arrest;
     - `hero_pawn`: a queue case whose laptop serial resurfaced in pawn 3 days later, plus a same-model, different-serial trap;
     - `hero_decoy`: a plausible group where one case violates spatiotemporal feasibility (to show the engine rejecting it);
     - `hero_weak`: a queue case with no leads (screening packet).
3. Tests:
   - determinism (same seed gives the same bytes);
   - counts and clearance ≈ 13% ± 1;
   - planted series feasible under `verify::MAX_URBAN_SPEED_KMH` / `MIN_ON_SCENE_MIN` using `core::geo`;
   - decoys violate their stated constraint;
   - no queue case has `mo`.

## W3: MCP server + recorder + agent definitions (`mcp.rs`, `record.rs`, `agents/`)
**`casefile mcp`:** rmcp 3.9 stdio server named `casefile`. Load `Store` from `root()`; never read ground truth. Tools, with JSON in/out and clear descriptions written for an LLM:
- `get_case{case_id}`
- `search_cases{neighborhood?, premise?, since?, until?, status?, limit<=50}`: summaries
- `similar_cases{case_id, k<=10}`
- `propose_clusters{threshold?}`
- `verify_series{case_ids}`
- `score_solvability{case_id}`: context computed from clusters and property
- `pawn_lookup{case_id}`
- `check_citations{text}`
- `request_approval{kind, subject, summary, payload}` → `{ticket_id, status:"pending", escalate_after_minutes:120}`. Never blocks. Appends to the audit log and `data/approvals.json`.
- `approval_status{ticket_id}`
- `draft_victim_update{case_id, language, message}`: stored as a draft pending approval. **There is no send tool.**
- `cost_model{scenario?}`

**`casefile record <agent> <input-id> [--model m] [--concurrency n --ids file]`:**
- Builds the prompt from `agents/<agent>/agent.json` (`model`, `allowed_tools`, `input` = which data to inline, e.g. case narrative) and runs:
  `claude -p --model <m> --system-prompt-file agents/<agent>/system.md --output-format stream-json --verbose --json-schema <schema> --mcp-config <temp json → this exe "mcp" with CASEFILE_ROOT> --strict-mcp-config --allowedTools <mcp__casefile__...> --no-session-persistence`
  Disable built-in tools; check `claude --help` for the exact flag names.
- Parses the stream-json lines and saves `data/recordings/<agent>/<input-id>.json` as a `RecordedRun` (store.rs), including the final structured output, tokens, cost and duration.
- `claude` binary: `$CLAUDE_BIN` or `claude` on PATH (on this machine: `%USERPROFILE%\.local\bin\claude.exe`).

**Agents** (instructions focused, non-conflicting, testable; each schema has `additionalProperties:false`):

| agent | model | tools | output |
|---|---|---|---|
| extractor | haiku | none (narrative inlined) | `{mo: Mo, items:[...serials found], notes}` (exact `Mo` enum names from types.rs) |
| triage | sonnet | score_solvability, similar_cases, pawn_lookup, get_case | `{disposition: assign\|screen_out\|link_review, rationale_with_citations, next_steps:[{step, why, lawful_basis_note, est_minutes}]}`: the domain judge's "list of things to do" |
| series_hunter | sonnet | propose_clusters, similar_cases, verify_series, get_case | `{hypotheses:[{case_ids, rationale_with_citations}]}` |
| skeptic | opus | verify_series, get_case, similar_cases | `{verdicts:[{case_ids, keep:bool, drop_case_ids, reasons_with_citations}]}`: argues AGAINST each hypothesis, relies on verify_series |
| packet_writer | sonnet | get_case, pawn_lookup, verify_series, check_citations | `{packet_markdown, citations_ok:bool}`: must call check_citations and fix issues |
| victim_liaison | haiku | get_case, draft_victim_update | `{language, message, plain_english_summary}`: calm, no suspect info, no promises |

## W4: web console (`server.rs`, `ui/`)
**`casefile serve [--port 8080]`:** axum. Static `ui/` via tower-http `ServeDir`. Store loaded once.
- `GET /api/queue`: demo queue: case summary, solvability, flags `{series_id?, pawn_hit?}`
- `GET /api/case/:id`: case, solvability, top-5 similar, pawn matches, recorded runs (extractor/triage/packet_writer/victim_liaison) if present
- `GET /api/series`: engine clusters touching the queue, each with `verify` plus recorded series_hunter/skeptic outputs
- `GET /api/replay/:agent/:id`: SSE replay of a RecordedRun's events with realistic pacing (`?speed=`), so tool calls appear live
- `POST /api/decision {actor, action, subject, detail}` → audit append; `GET /api/audit` → entries + chain status
- `GET /api/kpi`: `cost::compute` for all scenarios
- `GET /api/points?ids=`: lat/lon for the map

**UI**, one screen, 1280×720 friendly (recorded for the demo):
- **Left:** overnight queue.
- **Centre:** case card. Narrative with extracted fields highlighted; solvability bars with factor contributions; property hits (exact serial lead vs rejected trap); linked cases.
- **Right:** lead packet with citation chips (hover shows the cited field value) and a **next-steps checklist** with Accept / Reject + reason (Not lawful / Not available / Too resource-intensive / Other), audited.
- **Series view:** inline SVG map (projected lat/lon, no tiles), a timeline strip, verify checks as pass/fail chips with reasons, the skeptic's note, and an "Approve series alert" button.
- **Victim update draft** (Spanish) with Approve.
- **Audit drawer:** "chain intact ✓ (n entries)".
- **KPI strip** from `/api/kpi`.
- A persistent banner: "Synthetic data: Cascade City (fictional). AI suggests, people decide."
- Sober, professional look (use the `impeccable` skill guidance). Accessible contrast, keyboard operable, no external fonts or CDNs.
- Must degrade gracefully when recordings are missing.
