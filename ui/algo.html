1 · Pair score: how likely two burglaries share an offender

A logistic model over MO agreement, distance, time gap and shared behavioural signatures. Move the sliders: the bars show each term's push on the log-odds z, and the score is σ(z).

2 · Time sweep: only compare cases inside the 180-day link window

Brute force checks all n(n−1)/2 pairs. Sorted by offense time, each case only needs the cases after it until the gap passes the window, then the inner loop breaks. Same pairs survive, far fewer visited.

3 · Upper-bound pruning: skip the MO work when even a perfect match can't link

Distance and time are cheap; MO comparison is not. Assume the best case (MO similarity = 1, every signature shared). If that optimistic score is still below the threshold, the true score is too, so the pair is skipped. Shaded: pairs that still need MO work. The line is where the bound equals the threshold.

4 · Union-find clusters, re-split when a group chains too far

Edges are pairs at or above the threshold. Connected components (disjoint-set union with path halving) are candidate series. A component over 15 cases is usually chaining (A~B~C~D…), so it is re-split at threshold + 0.05 until it fits. Every group then goes to the verifier.

5 · Top-k similar cases: bounded min-heap with branch-and-bound

Keep the best k in a min-heap (O(n log k) instead of sorting all n). Once the heap is full, a candidate whose upper bound is below the current k-th best can't get in, so its MO work is skipped.

6 · Pawn matching with an inverted index

A pawn record can match a stolen item only if it shares the category (conflicting serial or similar description), the same normalised serial (exact lead, any category) or a marking (review candidate, any category). Under the rules every other record is a guaranteed no-match, so the index never compares them.
