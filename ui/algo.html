In plain English · 1 minute

Casefile helps detectives spot burglaries that were probably done by the same person, and checks every guess before a human sees it.

1

Read

An AI reads each burglary report and writes down how it happened: which door, what tool, what time of day, what was taken.

2

Compare

Every pair of burglaries gets a similarity score from 0 to 1. Same method, close together and close in time means a high score.

3

Fact-check

A plain calculator, not the AI, asks hard questions. Could one person physically get from one scene to the other in time? If not, the link is thrown out.

4

Detective decides

Only what survives reaches a detective, as a checklist. They accept or reject each step, and every decision is logged so it can be replayed later.

Stolen property

If a stolen laptop's serial number shows up at a pawn shop, that's a lead, not proof. Look-alike laptops with a different serial are rejected automatically.

Why not just ask an AI?

On the same 150 made-up cases, one big AI model was as accurate as we were. But it accepted 9 links that were physically impossible. Ours accepted 0. Checking travel time is arithmetic, and that's what calculators are for.

Fast, and the same answer every time

We made the engine 16 to 54 times faster, then proved the fast version gives exactly the same answers as the slow, obvious version. Same inputs, same output, every run.

What we don't claim

All data here is synthetic. A link is a reason to look, never a reason to arrest. Whether it saves time and solves cases has to be measured in a real pilot.

4 · Union-find clusters, re-split when a group chains too far

Edges are pairs at or above the threshold. Connected components (disjoint-set union with path halving) are candidate series. A component over 15 cases is usually chaining (A~B~C~D…), so it is re-split at threshold + 0.05 until it fits. Every group then goes to the verifier.

5 · Top-k similar cases: bounded min-heap with branch-and-bound

Keep the best k in a min-heap (O(n log k) instead of sorting all n). Once the heap is full, a candidate whose upper bound is below the current k-th best can't get in, so its MO work is skipped.

M1 · Distance and time between two cases

Great-circle distance (haversine, mean Earth radius \(R = 6371.0088\) km), for case locations \((\varphi_a,\lambda_a)\), \((\varphi_b,\lambda_b)\) in radians:

$$h = \sin^2\!\frac{\varphi_b-\varphi_a}{2} + \cos\varphi_a\cos\varphi_b\,\sin^2\!\frac{\lambda_b-\lambda_a}{2}, \qquad d(a,b) = 2R\arcsin\sqrt{h}$$

Each report has an offense window \([s, e]\) (the victim was away). Time apart uses window midpoints:

$$\mu_a = \tfrac{1}{2}(s_a + e_a), \qquad t(a,b) = \frac{|\mu_a - \mu_b|}{86\,400}\ \text{days}$$

M2 · MO similarity \(m(a,b) \in [0,1]\)

$$m = 0.20\,\mathbb{1}[\text{premise}] + 0.15\,\mathbb{1}[\text{entry pt}] + 0.15\,\mathbb{1}[\text{method}] + 0.10\,\mathbb{1}[\text{time band}] + 0.05\,\mathbb{1}[\text{weekday}] + 0.15\,J(P_a,P_b) + 0.20\,J(S_a,S_b)$$

\(\mathbb{1}[\cdot]\) is 1 only for an exact match on a known value (Unknown never agrees). \(P\) = property types taken, \(S\) = behavioural signatures (trimmed, case-insensitive). Weights sum to 1. A missing MO on either side gives \(m = 0\).

$$J(A,B) = \frac{|A\cap B|}{|A\cup B|} = \frac{|A\cap B|}{|A|+|B|-|A\cap B|}, \qquad J(\varnothing,\varnothing) := 0$$

Fast path: the 12 property types become a 12-bit mask, so \(J = \operatorname{popcount}(a \wedge b) / \operatorname{popcount}(a \vee b)\). Signatures are interned to sorted integer ids, and \(|S_a \cap S_b|\) is a linear merge walk. Same integers, same division, so the result is bit-identical to the set version.

M3 · Pair score

$$z(a,b) = -0.4 + 6.0\,m \;-\; 1.3\ln(1+d) \;-\; 0.9\ln(1+t) \;+\; 0.6\,\min(\sigma_{ab}, 3)$$ $$\text{score}(a,b) = \begin{cases} \sigma(z) & \text{both cases have an MO} \\ 0.5\,\sigma(z) & \text{otherwise} \end{cases} \qquad \sigma(z) = \frac{1}{1+e^{-z}}$$

\(\sigma_{ab} = |S_a \cap S_b|\) is the number of shared signatures. Log terms make decay steepest near zero distance and zero days (distance decay and temporal proximity in the burglary-linkage literature). Without an MO the best possible score is \(0.5\,\sigma(-0.4) \approx 0.2007\), so it can never pass 0.5. The score is exactly symmetric: components are computed in id order.

M4 · The upper bound, and why skipping is exact

Distance and time are cheap. The MO comparison is the expensive part. Before doing it, bound the score using only \(d\), \(t\) and list lengths:

$$\mathrm{UB}(a,b) = \sigma\!\Big(5.6 - 1.3\ln(1+d) - 0.9\ln(1+t) + 0.6\min\big(|S_a|, |S_b|, 3\big)\Big)$$
Claim. \(\text{score}(a,b) \le \mathrm{UB}(a,b)\), so \(\mathrm{UB} \lt \theta \Rightarrow \text{score} \lt \theta\) and the pair can be skipped without changing the edge set.
Proof. \(z\) is affine in \(m\) and in \(\min(\sigma_{ab},3)\), with positive coefficients 6.0 and 0.6. Also \(m \le 1\) (the weights sum to 1 and each indicator and Jaccard term is at most 1) and \(\sigma_{ab} \le \min(|S_a|,|S_b|)\). So \(z \le -0.4 + 6.0 + (\dots) = z_{\mathrm{UB}}\). \(\sigma\) is increasing, and the no-MO factor \(0.5 \le 1\) only lowers the score. In floating point, both sides use the same operations in the same order, and IEEE-754 addition and multiplication by a positive constant are monotone, so the inequality survives rounding. ∎

Measured on the 2,000-case seed set at \(\theta = 0.9\): 1,461,811 pairs inside the time window, 68,781 pass the bound (4.7% of them; 3.4% of all \(\binom{2000}{2}\) pairs), 761 become edges.

M5 · The pruning region in closed form

Setting \(\mathrm{UB} = \theta\) and solving gives the boundary curve. A pair is scored only if it lies inside:

$$1.3\ln(1+d) + 0.9\ln(1+t) \;\le\; 5.6 + 0.6\min(|S_a|,|S_b|,3) - \operatorname{logit}\theta, \qquad \operatorname{logit}\theta = \ln\frac{\theta}{1-\theta}$$

At \(\theta = 0.9\) (\(\operatorname{logit} = 2.197\)) with one signature, the right side is 4.003. That gives a maximum distance of \(e^{4.003/1.3}-1 \approx 20.7\) km at zero days, and a maximum gap of \(e^{4.003/0.9}-1 \approx 84.5\) days at zero distance. In \((\ln(1+d), \ln(1+t))\) coordinates the region is a triangle; in \((d,t)\) it is the convex-down curve in panel 3.

M6 · Time sweep: how many pairs it visits

Sort cases by \(\mu\). For case \(i\), scan forward and stop at the first \(j\) with \(\mu_j - \mu_i \gt W\) (\(W = 180\) days). Every later case is further away, so nothing is missed. The cost is \(O(n\log n + P_W)\), where \(P_W\) is the number of pairs within \(W\). If offense times are spread roughly uniformly over a span \(T\):

$$\Pr\big[|\mu_a-\mu_b| \le W\big] = 1 - \Big(1 - \frac{W}{T}\Big)^2 \quad\Rightarrow\quad P_W \approx \binom{n}{2}\Big[\,2\tfrac{W}{T} - \big(\tfrac{W}{T}\big)^2\Big]$$

Seed data: \(W/T \approx 180/365\) predicts 74.3%; measured 1,461,811 / 1,999,000 = 73.1%. For a multi-year archive (\(T \gg W\)) the share falls like \(2W/T\): 23% at 4 years, 6.5% at 15 years. That's where the sweep pays off most. A \(30\) km bounding box runs next; on a city-sized dataset it removes nothing (honest null).

M7 · Union-find components and re-split

Graph \(G_\theta = (V, E_\theta)\), \(E_\theta = \{(a,b) : \text{score}(a,b) \ge \theta\}\). Candidate series are the connected components of size \(\ge 2\), found with a disjoint-set forest using path halving (\(x \leftarrow \text{parent}(\text{parent}(x))\)), where the smaller index becomes the root so results don't depend on edge order. A component \(C\) with \(|C| \gt 15\) is treated as chaining (A~B, B~C, … without A~C) and re-split on \(G_{\theta+0.05}[C]\), recursively:

$$\text{split}(C, \theta) = \begin{cases} \{C\} & |C| \le 15 \\ \varnothing & \theta + 0.05 \gt 0.995 \\ \bigcup_{C' \in \text{comp}(G_{\theta+0.05}[C])} \text{split}(C', \theta+0.05) & \text{otherwise} \end{cases}$$

The depth is at most \(\lceil (0.995-\theta)/0.05 \rceil\): 2 levels at \(\theta = 0.9\). Thresholds only rise, so edges only disappear, and a re-split never merges. Output ids \(S\text{-}1, S\text{-}2, \dots\) follow each group's smallest case id, which makes the result deterministic.

M8 · Top-k similar cases with branch-and-bound

Rank candidates by the total order \((\text{score}\downarrow, \text{id}\uparrow)\). Keep a min-heap \(H\) of the best \(k\) seen so far: \(O(n\log k)\) time, \(O(k)\) memory, versus \(O(n\log n)\) for a full sort.

Cut. If \(|H| = k\) and \(\mathrm{UB}(q,c) \lt \min H\), then \(\text{score}(q,c) \le \mathrm{UB} \lt \min H\), so \(c\) can never enter the heap (it would also lose any tie, because the inequality is strict). Skipping its MO work leaves the result unchanged. ∎

M9 · The verifier (yes/no rules)

Hard: spatiotemporal feasibility, for every pair in a proposed series. One offender travelling at \(v = 40\) km/h door to door, needing at least 10 minutes on scene:

$$\underbrace{\frac{\max(e_b - s_a,\; e_a - s_b,\; 0)}{60}}_{\text{best-case minutes available}} \;\ge\; \underbrace{\frac{60\,d(a,b)}{40} + 10}_{\text{minutes needed}} \qquad\text{else } \textbf{FAIL}$$

Demo decoy: 15.9 km apart, 30 min available, \(60 \cdot 15.9/40 + 10 = 33.9\) min needed, so it fails. The windows give the most generous ordering, so FAIL means impossible even in the best case.

Hard: conflicting clearance. Two cases cleared by arrest of different people fail: one offender can't be two arrestees.
Soft: MO consistency. \(\bar m = \binom{|C|}{2}^{-1}\sum_{a\lt b} m(a,b)\): below 0.35 fails (soft), below 0.55 is weak.
Soft: property. Some property type must recur in at least two cases, else weak. Soft: spread. \(\max d \gt 12\) km is weak (burglars commute short).
Verdict = FAIL if any hard check fails; else WEAK if any soft check is weak or failed; else PASS. For each hard conflict, the case with the lower mean pair score to the rest is named as the one to drop.

M10 · Pawn matching rules, and why the index is complete

Serial normalisation: \(\nu(x)\) = uppercase, keep \([A\text{-}Z0\text{-}9]\) only (O and 0, I and 1 are not merged). For an item \(i\) and a pawn record \(p\) received after the offense window started:

$$\text{match}(i,p) = \begin{cases} \text{exact serial lead} & \nu_i,\nu_p \text{ present},\ \nu_i = \nu_p \\ \text{rejected: conflicting serial} & \nu_i \ne \nu_p,\ \text{same category} \\ \varnothing & \nu_i \ne \nu_p,\ \text{different category} \\ \text{review: shared marking} & \text{else if } M_i \cap M_p \ne \varnothing \\ \text{unresolved similar} & \text{else if same category and (brand}\wedge\text{model ok, or } J_{\text{tokens}} \ge 0.5) \\ \varnothing & \text{otherwise} \end{cases}$$
Lemma. \(\text{match}(i,p) \ne \varnothing \Rightarrow p \in \mathcal{B}_{\text{cat}}(c_i) \cup \mathcal{B}_{\text{serial}}(\nu_i) \cup \bigcup_{x\in M_i}\mathcal{B}_{\text{mark}}(x)\).
Proof by cases. An exact lead has \(\nu_p = \nu_i\), so it is in the serial bucket. A conflicting serial requires the same category, so it is in the category bucket. A shared marking puts it in a marking bucket. "Unresolved similar" requires the same category. Every other branch returns \(\varnothing\). ∎
So the index compares each item only with the union of its buckets, visited in record order, and returns exactly what brute force returns (fuzz-tested on all four outcomes).

Brute force: \(|I|\cdot|P| = 5{,}117 \times 1{,}500 \approx 7.7\)M comparisons, each re-normalising strings. Indexed: normalise once, then \(\sum_i |\text{buckets}(i)|\), about \(|I|\cdot|P|/12\) for 12 roughly balanced categories. Measured: 5.26 s → 98 ms.

M11 · Solvability score (queue order)

$$\text{solv} = 100\,\sigma\Big(-1.0 + 0.9x_{\text{wit}} + 0.8x_{\text{susp}} + 0.6x_{\text{veh}} + 0.7x_{\text{video}} + 0.5x_{\text{phys}} + 0.4x_{\text{trace}} - 0.3\ln(1+h) + 0.5x_{\text{series}} + 1.2x_{\text{pawn}}\Big)$$

The \(x\) terms are 0/1 facts and \(h\) is the window length in hours. Bands: below 25 weak, below 55 moderate, else strong. Each factor's contribution is computed by adding terms one at a time, \(\Delta_k = 100[\sigma(z_{k}) - \sigma(z_{k-1})]\), so contributions sum exactly to score − baseline. Hand-set to follow the direction of the solvability literature; this is not a calibrated probability.

M13 · Cost and clearance model (base scenario, worked)

Official baseline: \(N = 10{,}000\) cases/yr, 13% cleared, detective \$70/h, officer \$50/h, labour \$3.05M. Base inputs (assumptions): adoption \(a = .85\), screened share .40 at 30 min instead of 90, packet saves 20 min, evidence saves 10 officer-min.

$$\text{gross} = \underbrace{\tfrac{1}{60}\big[3{,}400(90-30) + 5{,}100\cdot 20\big]}_{5{,}100\ \text{det-h}}\cdot 70 + \underbrace{\tfrac{8{,}500\cdot 10}{60}}_{1{,}416.7\ \text{off-h}}\cdot 50 = \$427{,}833$$ $$L = \underbrace{1{,}300\cdot .30\cdot 1.5\cdot a}_{\text{linkage } 497.25} + \underbrace{N\cdot .35\cdot .10\cdot a\cdot(1-.20)}_{\text{property } 238} + \underbrace{120\,a}_{\text{triage } 102} = 837.25 \text{ new leads}$$ $$\Delta\text{clearances} = L\cdot\underbrace{.65}_{\text{complete}}\cdot\underbrace{.50}_{\text{convert}} - \underbrace{10}_{\text{screening loss}} = 262.1 \quad(\text{target } 325)$$ $$\text{false leads} = (497.25+238)\Big(\frac{1}{.80}-1\Big) = 183.8, \qquad \text{work} = \underbrace{544.2\cdot 2\,\text{h}\cdot 70}_{\$76{,}190} + \underbrace{183.8\cdot\tfrac{20}{60}\cdot 70}_{\$4{,}289}$$ $$\text{steady net} = 427{,}833 - \underbrace{62{,}000}_{\text{recurring}} - 80{,}479 = \$285{,}355 \;(9.36\%,\ \text{target } 15\%)$$ $$\text{year one} = .65\cdot 427{,}833 - 62{,}000 - 80{,}479 - \underbrace{130{,}000}_{\text{one-time}} = +\$5{,}613$$

Dollars are freed capacity, not cash. Scenario brackets: conservative 2.09% / +44.5, optimistic 15.39% / +457.9. Only optimistic meets either target. To reach +325 with everything else fixed, conversion would need 61.56%.

M14 · Audit hash chain

$$h_0 = \text{"genesis"}, \qquad h_k = \operatorname{SHA\text{-}256}\big(h_{k-1} \,\Vert\, \operatorname{JSON}(e_k \setminus \text{hash})\big)$$

Editing entry \(k\) changes \(h_k\) and breaks every later link, and verify reports the first bad sequence number. It is tamper-evident, not tamper-proof: someone who rewrites the whole file can recompute the chain, so production would anchor \(h_k\) externally.
